Introdução
A engenharia de dados é a área responsável por projetar, construir e manter a infraestrutura que coleta, armazena, processa e disponibiliza dados para análise. Envolve conhecimentos de bancos de dados, computação em nuvem, big data, programação e boas práticas de desenvolvimento. Este guia foi elaborado para ajudar você a entender os conceitos fundamentais e a resolver questões típicas de uma prova de certificação ou concurso na área.

1. Big Data
O que é Big Data?
Big Data refere-se a conjuntos de dados tão grandes e complexos que as ferramentas tradicionais de processamento não conseguem lidar com eles de forma eficiente. Seus princípios são frequentemente descritos pelos 5 Vs:

Volume: grande quantidade de dados.

Velocidade: dados gerados rapidamente (ex.: streams).

Variedade: diferentes formatos (estruturados, semiestruturados, não estruturados).

Veracidade: qualidade e confiabilidade dos dados.

Valor: extrair insights úteis.

Tipos de processamento
Batch (lote): processa grandes volumes de dados em intervalos programados (ex.: diariamente).

Streaming (tempo real): processa dados continuamente à medida que chegam.

Interativo (ad hoc): consultas sob demanda, geralmente exploratórias.

ETL vs ELT
ETL (Extract, Transform, Load): os dados são extraídos, transformados em um servidor de staging e depois carregados no destino.

ELT (Extract, Load, Transform): os dados são extraídos e carregados primeiro no destino (ex.: data lake) e depois transformados conforme necessário. É mais comum em arquiteturas modernas com ferramentas como Spark.

Camadas de dados
Source of Record (SoR): sistemas de origem, onde os dados são gerados (ex.: bancos transacionais).

Source of Truth (SoT): camada curada, com dados limpos e confiáveis para análise.

Specialized: camadas específicas para determinados domínios ou aplicações (ex.: data marts).

Tipos e formatos de dados
Estruturados: tabelas com linhas e colunas (ex.: CSV, Parquet, ORC, Avro).

Semiestruturados: possuem alguma organização, mas não são rígidos (ex.: JSON, XML).

Não estruturados: sem formato predefinido (ex.: imagens, vídeos, textos livres).

Qualidade de dados
Métricas comuns: completeza, unicidade, consistência, validade, precisão. É importante aplicar validações em cada camada do pipeline.

Hadoop e MapReduce
Hadoop: ecossistema de software para armazenamento e processamento distribuído. Componentes principais: HDFS (armazenamento) e YARN (gerenciamento de recursos).

MapReduce: modelo de programação que divide o processamento em duas fases: Map (processa dados em paralelo) e Reduce (agrega resultados). O nó Master coordena, enquanto os Slaves executam as tarefas. O nó Master não deve armazenar ou processar dados diretamente.

Apache Spark
Framework de processamento em memória, mais rápido que MapReduce para muitas cargas de trabalho.

Oferece APIs para Java, Scala, Python e SQL.

Operações de transformação: map, filter, flatMap, distinct, join, etc. (nota: joinstep não é uma operação padrão).

Questões Resolvidas
1. Qual é o mecanismo de consulta utilizado no Amazon Athena?
Alternativa correta: Presto
Explicação: O Amazon Athena é um serviço de consulta interativa que permite executar queries SQL diretamente em dados armazenados no S3. Ele utiliza o mecanismo Presto, um motor de consultas distribuído de código aberto, otimizado para análises rápidas em grandes volumes de dados.

2. Ao trabalhar com dados em uma arquitetura de data lake, qual das seguintes estratégias é recomendada para garantir a qualidade dos dados?
Alternativa correta: Aplicação de validações de qualidade de dados em cada camada do data lake
Explicação: Em um data lake, os dados passam por diferentes camadas (raw, trusted, refined). Aplicar validações em cada etapa garante que problemas sejam detectados precocemente e que os dados downstream sejam confiáveis. As outras opções (única camada, arquivo único, sem monitoramento) são práticas inadequadas.

3. SQOOP é uma ferramenta do ecossistema Hadoop cuja principal função é:
Alternativa correta: Importar dados de sistemas gerenciadores de banco de dados relacionais
Explicação: O Apache Sqoop foi desenvolvido para transferir dados entre o Hadoop (HDFS, Hive, HBase) e bancos de dados relacionais (como MySQL, PostgreSQL, Oracle). Ele permite importar e exportar dados de forma eficiente.

4. Por padrão Spark persiste dados em memória ou em disco. Sobre a afirmação acima, marque a melhor opção:
Alternativa correta: Dados podem ser persistidos de forma híbrida, em memória e disco
Explicação: O Spark permite que os dados sejam persistidos (cacheados) em memória para acelerar processamentos repetitivos. No entanto, se não houver memória suficiente, ele pode armazenar dados em disco. Além disso, é possível configurar níveis de persistência como MEMORY_ONLY, DISK_ONLY ou MEMORY_AND_DISK.

5. Qual opção apresenta a definição correta para Replicação e Partição, respectivamente?
Alternativa correta: Dados são copiados para diferentes nós / Dados são divididos entre diferentes nós
Explicação: Em sistemas distribuídos:

Replicação: cópias dos dados são mantidas em múltiplos nós para garantir tolerância a falhas e alta disponibilidade.

Partição (sharding): os dados são divididos em fragmentos e distribuídos entre nós para paralelizar o processamento.

6. Map reduce opera no conceito Master e Slave. Qual das tarefas abaixo não é recomendada para o nó Master?
Alternativa correta: Manter e processar dados
Explicação: No modelo Master-Slave, o nó Master é responsável por coordenar as tarefas, agendar execuções, manter metadados e balancear a carga. Ele não deve armazenar ou processar dados diretamente, pois isso poderia sobrecarregá-lo e comprometer a coordenação do cluster.

7. Uma das características do HDFS é a replicação transparente. Qual opção abaixo melhor define este conceito?
Alternativa correta: Arquivos são distribuídos automaticamente entre os nós da rede
Explicação: No HDFS, os arquivos são divididos em blocos (ex.: 128 MB) e cada bloco é replicado automaticamente em múltiplos nós (padrão: 3 réplicas). Isso ocorre de forma transparente para o usuário, garantindo tolerância a falhas e disponibilidade.

8. São exemplos de operações de transformação em Spark, EXCETO:
Alternativa correta: Joinstep
Explicação: As operações de transformação no Spark incluem map, filter, flatMap, distinct, join (que é uma operação de transformação, mas o nome correto é join). "Joinstep" não é uma operação reconhecida no Spark.

9. Partition e Bucketing são mecanismos do Hive de particionar dados para otimizar consultas. Uma tabela possui uma coluna e-mail, qual seria a melhor técnica de particionamento e por quê?
Alternativa correta: Bucketing, pois a cardinalidade dos dados será muito grande
Explicação:

Partitioning é ideal para colunas com baixa cardinalidade (ex.: país, ano), pois cria diretórios separados.

Bucketing é melhor para colunas com alta cardinalidade (ex.: e-mail, ID), pois distribui os dados em um número fixo de buckets (arquivos) dentro de cada partição, melhorando a eficiência de consultas com joins e agregações.

2. AWS (Amazon Web Services)
Principais serviços de dados
S3: armazenamento de objetos, base para data lakes.

Glue: serviço serverless de ETL, com catálogo de dados (Glue Data Catalog) e crawlers para descobrir esquemas.

Redshift: data warehouse em nuvem, colunar, escalável.

Athena: consultas SQL interativas em dados no S3, usando Presto.

EMR: cluster gerenciado para frameworks como Spark, Hadoop, Flink.

Lambda: computação serverless para execução de código em resposta a eventos.

Monitoramento e custos
CloudWatch: coleta métricas, logs e eventos; permite criar alarmes.

Cost Explorer: visualiza e analisa custos da AWS.

SNS: serviço de notificações (e-mail, SMS, HTTP).

Segurança e rede
IAM: gerenciamento de identidades e permissões.

Security Groups: firewalls virtuais para instâncias.

Route 53: serviço de DNS.

20. Imagine que você está trabalhando em uma empresa de análise de dados, precisando realizar transformações e limpeza de dados em um pipeline de ingestão. 3. Banco de Dados
Modelagem de dados
Conceitual: alto nível, descreve entidades, atributos e relacionamentos, sem se preocupar com implementação.

Lógica: detalha tabelas, colunas, chaves, mas ainda independente de SGBD.

Física: específica para um banco de dados, incluindo tipos de dados, índices, partições.

Chaves
Primária: única e não nula, identifica cada linha.

Estrangeira: referencia chave primária de outra tabela.

Substituta (surrogate): chave artificial (ex.: ID sequencial) usada em modelos dimensionais para garantir unicidade e evitar dependência de chaves naturais.

SQL
Comandos básicos: SELECT, INSERT, UPDATE, DELETE. Junções: INNER JOIN, LEFT JOIN, RIGHT JOIN, FULL OUTER JOIN. Subconsultas com EXISTS, IN.

Data Warehouse e Data Mart
Data Warehouse (DW): repositório centralizado que integra dados de várias fontes, com visão corporativa, granularidade detalhada e histórico completo.

Data Mart (DM): subconjunto do DW, focado em uma área de negócio (ex.: vendas, marketing), com menor granularidade e histórico limitado.

NoSQL
Bancos não relacionais: chave-valor, documentos, colunas, grafos.

25. Leia as afirmações abaixo sobre DW (Data Warehouse) e DM (Data Marts):
I. Sob o ponto de vista de abrangência, o DW modela as necessidades sob uma visão específica/departamental;

Correção: Na verdade, a afirmativa I é sobre DW com visão departamental – isso é característica de DM. Então I é falsa. II é verdadeira (DW tem maior detalhe). III é verdadeira (DM tem histórico essencial). IV é falsa. Logo, verdadeiras: II e III. A opção correspondente é "II e III". Na prova, a resposta marcada foi I e III, o que está errado. Vamos considerar a resposta correta como II e III.

27. Qual opção melhor explica a necessidade de uma chave substituta em um modelo dimensional?

A opção marcada fala em "não permitir valores repetidos", o que é uma consequência, mas a principal função é manter a integridade e rastreabilidade.

5. DevOps
Conceitos
DevOps: conjunto de práticas que integra desenvolvimento (Dev) e operações (Ops) para melhorar a colaboração, automação e entrega contínua.

Shift-left testing: prática de realizar testes o mais cedo possível no ciclo de desenvolvimento, reduzindo custos e aumentando a qualidade.

Versionamento: Git é a ferramenta mais comum para controle de versão.

Observabilidade: monitoramento, logs e rastreamento para entender o estado interno de sistemas.

Questões Resolvidas
33. No âmbito de DevOps, o termo “shift left testing” significa que os testes devem:

6. Data Mesh
O que é Data Mesh?
É uma abordagem descentralizada para arquitetura de dados, baseada em quatro princípios:

Domínios orientados a negócio: os dados são organizados por domínios (ex.: vendas, clientes), cada um com sua própria equipe.

Dados como produto: cada domínio trata seus dados como um produto, com qualidade e documentação.

Plataforma de autosserviço: infraestrutura que facilita a criação e consumo de produtos de dados.

Governança federada: regras comuns, mas com autonomia dos domínios.

Ingestão no Data Mesh
Refere-se ao processo de coletar dados de fontes (internas ou externas) e disponibilizá-los como produtos de dados, seguindo os princípios de domínio e propriedade.

Qualidade no Data Mesh
Recomenda-se:

Testes automatizados de qualidade.

Definição e monitoramento de métricas.

Padronização flexível (não rígida) para atender cada domínio.

2.7 Sistemas Distribuídos e Hadoop
Sistemas distribuídos são compostos por múltiplos computadores (nós) que trabalham juntos para parecer um único sistema. Eles oferecem escalabilidade e tolerância a falhas.

Apache Hadoop é um framework de código aberto para processamento distribuído de grandes volumes de dados. Seus principais componentes:

HDFS (Hadoop Distributed File System): sistema de arquivos distribuído que divide os dados em blocos e os replica em vários nós para tolerância a falhas.

YARN (Yet Another Resource Negotiator): gerencia recursos do cluster e agenda tarefas.

MapReduce: modelo de programação para processamento paralelo.

2.8 MapReduce
MapReduce é um modelo de programação que divide o processamento em duas fases:

Map: processa dados em paralelo, gerando pares chave-valor intermediários.

Reduce: agrega os resultados, combinando valores associados à mesma chave.

Exemplo: Contar palavras em um conjunto de documentos. Cada nó mapeia as palavras e conta ocorrências locais; depois, o reduce soma as contagens de cada palavra.

No Hadoop, há um nó Master (ResourceManager) que coordena as tarefas, e nós Slaves (NodeManagers) que executam as tarefas. O nó Master não deve armazenar ou processar dados diretamente para não se tornar um gargalo.

2.9 Apache Spark
Apache Spark é um framework de processamento em memória, mais rápido que MapReduce para muitas cargas de trabalho. Oferece APIs em Java, Scala, Python e SQL.

Características:

Processamento em memória (pode usar disco se necessário).

Suporte a batch, streaming, SQL, machine learning e grafos.

Operações de transformação: map, filter, flatMap, distinct, join, etc. (nota: joinstep não é uma operação padrão).

Persistência: dados podem ser persistidos em memória (MEMORY_ONLY), disco (DISK_ONLY) ou ambos (MEMORY_AND_DISK).

3.2 Serviços de Computação
EC2 (Elastic Compute Cloud): máquinas virtuais sob demanda. Você escolhe o sistema operacional, tamanho, armazenamento, etc.

Lambda: computação serverless; execute código em resposta a eventos sem gerenciar servidores. Ideal para tarefas curtas e event-driven.

3.3 Serviços de Integração
SQS (Simple Queue Service): fila de mensagens para desacoplar componentes de aplicação.

SNS (Simple Notification Service): serviço de notificações push para e-mail, SMS, HTTP, etc.

API Gateway: cria, publica e gerencia APIs.

Route 53: serviço de DNS (Domain Name System) que traduz nomes de domínio em endereços IP.

CodePipeline: serviço de CI/CD para automatizar entregas de software.

3.4 Segurança e Identidade
IAM (Identity and Access Management): gerencia usuários, grupos, permissões e roles. Controla quem pode acessar quais recursos.

KMS (Key Management Service): cria e gerencia chaves de criptografia.

3.5 Armazenamento
S3 (Simple Storage Service): armazenamento de objetos, altamente durável e escalável. Base para data lakes.

RDS (Relational Database Service): bancos de dados relacionais gerenciados (MySQL, PostgreSQL, etc.).

DynamoDB: banco NoSQL chave-valor e documento, totalmente gerenciado.

EFS (Elastic File System): sistema de arquivos compartilhado para EC2.

Storage Gateway: conecta infraestrutura on-premises com armazenamento na nuvem.

3.6 Ferramentas de Dados
Glue: serviço serverless de ETL. Inclui:

Glue Data Catalog: catálogo de metadados centralizado.

Glue Crawlers: percorrem dados no S3 e inferem esquemas, criando tabelas no catálogo.

Glue Jobs: executam scripts ETL (baseados em Spark) em ambiente gerenciado.

Redshift: data warehouse colunar, otimizado para consultas analíticas. Suporta:

COPY: comando eficiente para carregar dados do S3.

Redshift Spectrum: consulta dados diretamente no S3, sem carregar.

Athena: serviço de consultas SQL interativas diretamente em dados no S3, usando o motor Presto. Suporta diversos formatos (CSV, JSON, Parquet, ORC, Avro) e compressão (LZO, Snappy, GZIP).

EMR (Elastic MapReduce): cluster gerenciado para frameworks como Spark, Hadoop, Hive, Flink. Você escolhe o tamanho e paga por hora.

3.7 Monitoramento e FinOps
CloudWatch: coleta métricas, logs e eventos. Permite criar alarmes (ex.: uso de CPU, tamanho do bucket) e dashboards.

Cost Explorer: ferramenta para visualizar e analisar custos da AWS, ajudando a otimizar gastos.

SNS: usado em conjunto com CloudWatch para enviar notificações por e-mail, SMS, etc.

FinOps é a prática de gerenciar custos em nuvem, combinando finanças, tecnologia e negócios para tomar decisões informadas.

4. Banco de Dados
4.1 Conceitos Fundamentais
Um banco de dados é uma coleção organizada de dados armazenados eletronicamente. Os principais tipos:

Relacionais (SQL): organizam dados em tabelas com linhas e colunas, usando SQL para consultas. Ex.: MySQL, PostgreSQL, Oracle.

Não relacionais (NoSQL): flexíveis, adequados para dados não estruturados ou semiestruturados. Ex.: MongoDB, Cassandra, Redis.

4.2 Modelagem de Dados (Conceitual, Lógica, Física)
Modelagem Conceitual: alto nível, descreve entidades, atributos e relacionamentos, sem se preocupar com implementação. Ex.: diagrama entidade-relacionamento (DER) com "Cliente", "Produto", "Venda".

Modelagem Lógica: detalha tabelas, colunas, chaves, tipos de dados, mas ainda independente de SGBD. Ex.: tabela Cliente com campos id_cliente (INT), nome (VARCHAR).

Modelagem Física: específica para um banco de dados, incluindo índices, partições, otimizações. Ex.: CREATE TABLE com tipos específicos do PostgreSQL.

4.3 Chaves (Primária, Estrangeira, Substituta)
Chave Primária (Primary Key): identifica unicamente cada linha em uma tabela. Deve ser única e não nula. Pode ser simples (uma coluna) ou composta (várias colunas).

Chave Estrangeira (Foreign Key): referencia a chave primária de outra tabela, estabelecendo um relacionamento.

Chave Substituta (Surrogate Key): chave artificial (ex.: ID sequencial) usada em modelos dimensionais para garantir unicidade e evitar dependência de chaves naturais (que podem mudar). Exemplo: em uma dimensão "Cliente", a chave natural poderia ser o CPF, mas se o CPF mudar (raro), ou se houver clientes sem CPF, usa-se um ID interno.

4.4 SQL Básico e Intermediário
Comandos essenciais:

SELECT: consultar dados. Ex.: SELECT nome, idade FROM clientes WHERE cidade = 'São Paulo';

INSERT: inserir dados. Ex.: INSERT INTO clientes (nome, idade) VALUES ('João', 30);

UPDATE: atualizar dados. Ex.: UPDATE clientes SET idade = 31 WHERE nome = 'João';

DELETE: deletar dados. Ex.: DELETE FROM clientes WHERE nome = 'João';

Junções (JOIN):

INNER JOIN: retorna apenas linhas com correspondência em ambas as tabelas.

LEFT JOIN: retorna todas as linhas da tabela à esquerda, mesmo sem correspondência à direita.

RIGHT JOIN: análogo ao LEFT, mas com a tabela à direita.

FULL OUTER JOIN: retorna todas as linhas de ambas, preenchendo com NULL onde não há correspondência.

Subconsultas:

EXISTS: verifica se uma subconsulta retorna algum registro.

IN: verifica se um valor está em uma lista ou subconsulta.

4.5 Data Warehouse e Data Mart
Data Warehouse (DW): repositório centralizado que integra dados de várias fontes, com visão corporativa. Características:

Granularidade detalhada (dados em nível de transação).

Histórico completo.

Otimizado para consultas analíticas.

Data Mart (DM): subconjunto do DW, focado em uma área de negócio (ex.: vendas, marketing). Características:

Menor granularidade (dados agregados).

Histórico limitado ao necessário para análises departamentais.

4.6 Bancos NoSQL
Principais categorias:

Categoria	Descrição	Exemplos
Chave-Valor	Armazena pares chave-valor, acesso rápido por chave.	Redis, DynamoDB
Orientados a Documentos	Armazena documentos semiestruturados (JSON, BSON).	MongoDB, Couchbase
Orientados a Colunas	Armazena dados em colunas, otimizado para consultas analíticas.	Cassandra, HBase
Grafos	Armazena nós e arestas, ideal para dados altamente conectados.	Neo4j, Amazon Neptune
5. Programação
5.1 Algoritmos e Lógica de Programação
Um algoritmo é uma sequência finita de passos (instruções) para resolver um problema ou realizar uma tarefa. Exemplos: receita de bolo, instruções de montagem de um móvel.

Lógica de programação envolve o uso de estruturas de controle para criar algoritmos executáveis por computadores.

5.2 Estruturas de Controle
Condicionais: if, else, switch – executam blocos de código baseados em condições.

Loops: for, while – repetem blocos de código.

Operadores lógicos: AND, OR, NOT – combinam condições.

5.3 Programação Distribuída
Conceitos básicos:

Paralelismo: dividir tarefas em partes que podem ser executadas simultaneamente em múltiplos processadores ou máquinas.

Tolerância a falhas: capacidade de continuar operando mesmo com falhas em alguns nós.

Frameworks como Hadoop e Spark abstraem a complexidade, permitindo que o desenvolvedor escreva código como se estivesse em uma única máquina.

6. DevOps
6.1 O que é DevOps?
DevOps é um conjunto de práticas que integra desenvolvimento (Dev) e operações (Ops) para melhorar a colaboração, automação e entrega contínua de software. Pilares:

Cultura: colaboração e responsabilidade compartilhada.

Automação: pipelines de CI/CD, infraestrutura como código.

Medição: monitoramento e logging.

Compartilhamento: feedback contínuo.

6.2 Shell Script
Shell script são programas escritos para o shell do sistema operacional (ex.: Bash no Linux). São usados para automatizar tarefas como manipulação de arquivos, execução de comandos, agendamento de jobs.

Exemplo simples:

bash
#!/bin/bash
echo "Backup iniciado"
cp -r /dados /backup
echo "Backup concluído"
6.3 Versionamento com Git
Git é um sistema de controle de versão distribuído. Comandos básicos:

git init: inicia um repositório.

git add: adiciona arquivos à área de staging.

git commit: cria um commit com as alterações.

git push: envia commits para um repositório remoto.

git pull: atualiza o repositório local com alterações remotas.

Branching: ramificações para desenvolver funcionalidades isoladamente (ex.: feature-branch). Depois, faz-se merge com a branch principal.

6.4 Observabilidade
Observabilidade é a capacidade de entender o estado interno de um sistema a partir de dados externos (logs, métricas, traces). Práticas:

Logs: registros de eventos, usados para debugging e auditoria.

Métricas: dados numéricos ao longo do tempo (ex.: CPU, requisições por segundo).

Tracing: rastreamento de requisições através de serviços distribuídos.

Ferramentas: CloudWatch, ELK Stack, Prometheus, Grafana.

7. Data Mesh
7.1 Princípios do Data Mesh
Data Mesh é uma abordagem descentralizada para arquitetura de dados, proposta por Zhamak Dehghani. Baseia-se em quatro princípios:

Domínios orientados a negócio: os dados são organizados por domínios de negócio (ex.: vendas, clientes, estoque), cada um com sua própria equipe (produto de dados).

Dados como produto: cada domínio trata seus dados como um produto, com qualidade, documentação, e contratos claros.

Plataforma de autosserviço: infraestrutura que facilita a criação, governança e consumo de produtos de dados pelos domínios.

Governança federada: regras e padrões comuns, mas com autonomia dos domínios para decidir como implementá-los.

7.2 Data Mesh vs Data Lake
Data Lake: repositório centralizado de dados brutos, geralmente gerenciado por uma equipe central. Pode levar a gargalos e falta de agilidade.

Data Mesh: descentraliza a propriedade e a responsabilidade, promovendo agilidade e escalabilidade, mas requer maturidade em governança e cultura organizacional.

7.3 Ingestão e Qualidade no Data Mesh
Ingestão: processo de coletar dados de fontes (internas ou externas) e disponibilizá-los como produtos de dados, seguindo os princípios de domínio. Cada domínio é responsável por ingerir e expor seus dados.

Qualidade: práticas recomendadas:

Testes automatizados de qualidade.

Definição e monitoramento de métricas (completude, unicidade, etc.).

Padronização flexível: cada domínio pode usar formatos adequados, desde que siga contratos de interoperabilidade (evitar padronização rígida que engesse).

Questão 10: Partition vs Bucketing
Pergunta: Partition e Bucketing são mecanismos do Hive de particionar dados para otimizar consultas. Uma tabela possui uma coluna e-mail, qual seria a melhor técnica de particionamento e por quê?

Não sei a resposta

Bucketing, pois a cardinalidade dos dados será muito grande

Partition, pois a cardinalidade dos dados será pequena

Bucketing, pois a cardinalidade dos dados será pequena

Resposta correta: Bucketing, pois a cardinalidade dos dados será muito grande
Explicação:

Partitioning é ideal para colunas com baixa cardinalidade (ex.: país, ano), pois cria diretórios separados.
